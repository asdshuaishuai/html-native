# handwired 研究笔记 —— 对 html-native 的理念提炼与映射

> 研究对象: https://github.com/chenglou/handwired (2026-10 快照)
> 记录: 2026-10-17 · 本文档提炼其架构与理念, 并映射到 hn 引擎的组件。
> 口径同 ISSUES.md: ✅ 已落地 · 📋 可采纳(排期) · ❌ 不采纳(理由)

## 一、handwired 是什么

把**普通 JavaScript UI 代码**编译成一个**冻结的数值程序**——一条固定的
FP32 运算列表(加权求和 + ReLU 乘积 + 布尔舍入 + 表读, 共 4 种指令),
作者称之"神经网络": 无需训练(权重手写)、精确(与原 JS 逐位对齐)、
且完全可微(可解冻权重训练, 或接在 nanoGPT 后端端到端训练)。

关键转译: `if/else` → 两支全算 + ReGLU 门选择; `while` 循环 → 计数/
树/表/每项同代价(程序每帧全量跑, 不能提前退出); `table[i]` → indexRead
指令。运行时在 JS CPU 求值, JSON search demo 写成 WebGPU shader。

**HandwiredOS**: 一个 3 窗口 + dock 的桌面, 234 个源 cell、4,646 条活
运算、130 层、9,909 权重——由**一个程序**驱动: 焦点/层叠/拖拽/缩放/
窗口控制/dock/弹簧动画/Photos 布局/Monitor 自举列表。UI 是编译产物,
运行期零分支、零循环、零 GC 压力。

## 二、执行模型(对渲染引擎的启示)

| 概念 | handwired | 对 hn 的映射 |
|---|---|---|
| 源表 | Float32Array, cell = 常量/输入/事件位/状态 | hn 的 cell ≈ 样式字段 + ext_clock + 滚动偏移 |
| 线(wire) | 数值位置, 程序读旧写新 | hn 无此层——显示列表是"重建式", 非数据流 |
| 层(layer) | 依赖深度分桶 → 矩阵乘并行 | hn 布局/绘制已按树序, 无分层调度(📋 WebGPU 化时值得看) |
| 确定性求值 | 参考求值器与编译求值器 `===` 逐位一致, 测试验证 | hn 的 render_probe 跨架构确定性是同思想(绘制层); **动画时钟尚未逐位确定** → 本轮落地 |
| 声明(assume) | 范围/栅格/one-hot 是"承诺", 驱动优化降级 | hn 无对应; ❌ 不采纳(收益在 GPU 编译, hn 是软件光栅) |

## 三、已落地的理念

### ✅ 1/64ms 时间栅格 + 栅格上做差(本轮落地)

handwired: 帧时间戳与事件时间戳先量化到 1/64ms 栅格, **再做差**——任意
拆分的时间跨度相加严格相等, 存储状态跨帧率逐位一致(10/30/60/120fps
同一事件序列重放出同一画面, 500ms 停顿也一致)。

hn 落地: daemon pump 与 hn_app 真窗循环的帧时间戳量化到 1/64ms 栅格
(double)再做差出 dt。此前 daemon 用整数毫秒截断、hn_app 用整毫秒钟
——同一墙钟跨度在不同帧率下累加出不同的动画时钟。栅格化后, 过渡/
关键帧/平滑滚动的采样点在任意帧率下落在同一条缓动曲线上(±1/128ms)。

### ✅ 与既有 250ms 长眠限步的关系

hn 的 dt 上限 250ms 保留(手=handwired 的 snap 语义变体: 超预算不回放,
直接钳制)。handwired 的 snap 是"每个动画对象吸到目的地", hn 的过渡是
闭式缓动(elapsed→值), 大 dt 自然落到终态——语义已等价, 无需另做。

## 四、📋 可采纳(排期, 按价值排序)

### ✅ 1. 事件在时间戳处应用, 状态只在事件/整定点写回(2026-10-21 落地)
handwired: 一帧内每个不同时间戳的事件各做一次求值(弹簧先步进到该
时间戳再应用事件); 状态写回只发生在事件与 settle 整定点, 帧尾求值跑
在表格**副本**上。收益: 新目的地在事件后 ≤4ms 就开始拉动(而非等到下
帧), 且存档逐位可重放。

hn 落地(rt/hn_rt.c):
- `rt_mono_q()`: 单调钟 1/64ms 栅格量化(与帧时间戳同一手势; Win=QPC,
  POSIX=CLOCK_MONOTONIC, 自包含不拉平台层)。
- 四个输入入口(button/pointer_move/key/scroll)先调 `rt_events_advance`:
  动画钟推进到**事件到达时刻**, 消耗量记 `ev_consumed_ms`。
- `hn_rt_frame`: 动画钟推进扣除 `ev_consumed_ms`(同一真实跨度恰推进一次:
  事件时刻 + 帧尾余量; poll_clock 保持墙钟全量)。**实测判据**: 1s 线性
  变色, 事件后 500ms 虚拟步进 → 精确中点色 G=100; 999ms → G≈0.2;
  1000ms → 终态; 超步进不回退(events_probe §14, 81 断言全绿)。
- 无 pd 的 click 监听器跑过后补**全路径重算** —— 过渡目标(新目的地)在
  事件时刻启动, 不等下帧(旧口径 return 0, 过渡晚一拍, 实测 500ms 只走 ~0)。

### 2. settle check + 固定模拟时间整定点
handwired: 弹簧每 64ms 模拟时间做一次 settle 检查(0.01px 内且速度
≤0.01px/s → 落位并停), 动画停在同一模拟时刻, 与帧率无关。
hn 映射: HN_EASE_SPRING 目前是缓动曲线(时间参数化), 天然"停"在
duration 处; 平滑滚动(streams/anchors)有自己的推进。真正的弹簧积分器
(物理弹簧而非缓动近似)是路线图项——落地时直接采用"固定步长 + 整定点
settle + snap 上限"三件套, 不要自己发明。

### 3. 命中测试打在目的地矩形而非绘制矩形
handwired/chenguini ui.md: 移动中的元素, 点击判定用弹簧**目的地**矩形
——快速连点工作正常(toast 连关三个), 不会点进还没滑到的位置; 拖拽
起点除外(要抓得住画在哪)。
hn 映射: hit_walk 用 n->bx/by(当前布局盒)。对带 transition 的元素,
目的地 = 新样式的布局盒——hn 的级联在布局前完成, 布局盒**已经是目的
地**(transition 存在 anim 插值层, 不改布局盒)。即: hn 的命中天然打在
目的地 ✓ 已等价, 文档记录防回归。

### 4. 内容按目的地尺寸布局, 帧只做动画+裁剪
HandwiredOS: 窗口内容盒在目的地一变就按新尺寸布局, 中间帧只动画外框
并裁剪内容——内容每次目的地变更只布局一次, 不随中间尺寸反复布局。
hn 映射: transition 不触发重布局(布局盒即目的地) ✓ 已等价。

### 5. 前缀网络(prefix networks)与树形归并
Sklansky/Brent-Kung 前缀和把"每行顶边"这类链式依赖从 n 层压到 log n
层——GPU 化时的分层调度蓝图; CPU 上操作数更多, 作者自己也说 CPU 保持
循环更快。📋 WebGPU 化渲染/布局时再看。

## 五、❌ 不采纳

- **UI 即单个数值程序**: hn 的定位是 HTML/CSS 引擎(级联/布局/绘制管
  线), 把作者 JS 编译成 FP32 运算列表是另一条产品路线(且作者明说没有
  现成 JS→程序的工具, 要用 builder 重写)。有价值的部分(确定性、时序、
  命中语义)已按上文分别采纳。
- **FP32 逐位舍入纪律**(roundAffine 保项序等): 服务于"编译求值器与参
  考求值器 ==="的自证。hn 的确定性锚是跨架构渲染一致, 不需要运算级
  逐位协议。
- **训练/可微**: 有趣但离渲染引擎远; 若未来 hn-anim 要"学习缓动",
  reglu 网络可微是个参考。

## 六、本轮实测与验证(2026-10-21 复核)

- `bun test tests/runtime`(Bun 1.3.14): **174 pass / 0 fail**, 155,853
  个 expect —— 参考求值器与编译求值器对随机程序的逐位一致性有实测覆盖。
- `bun lab/runtime-cost/report.ts`(M 系列 CPU): window manager
  **234 cell / 4,646 live ops / 130 层 / 9,909 权重, 每帧求值 42.86µs**
  (最快后端); candidate gallery 3.07µs; 小变换 0.03µs。即: 一个完整
  桌面交互模型的数值求值开销远低于 1 帧预算 —— "程序每帧全量跑"的
  可行性是有实测背书的。
- 本地快照 /tmp/handwired(与上游同结构); 测试与成本报告均可本地复跑。
