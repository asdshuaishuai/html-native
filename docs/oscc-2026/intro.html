html-native · Neb一 · 项 目 背 景
01 — 项 目 背 景

AI 交互 UI 的第一公里：agent 画得出来，住不进桌面

今天 agent 生成 UI 的事实标准是"吐一张网页"：渲染结果取决于用户装了什么浏览器、内核百兆起步、内存黑洞；而且网页只能是网页——agent 会画界面，却不会让界面"住"在桌面上。对 agent 而言还多一堵墙：生成的东西无法被机器验证——渲染对不对全靠人眼，回归全靠重 roll。

WebView 内核百兆起步

Electron/Tauri 系每应用捆绑一份浏览器内核；内存与启动成本与"agent 高频生成、用完即弃"的形态天然冲突。

AI 生成 UI 不可验证

渲染像素没有机器口径，改一版全靠人眼对照；没有"探针断言"这种可进 CI 的验证层。

桌面形态缺位

网页不会悬浮、不会穿透点击、关掉就忘、重启不回——桌宠/数字人/常驻小组件这些"桌面原生形态"没有原语。

html-native 的回答：自研 C99 渲染引擎 Neb（NO-WEB）——agent 写 hn 编码（HTML 语法），引擎直接渲染成桌面级原生窗；渲染口径由 24 个探针、1145+ 项断言钉死，每轮回归逐值对账；桌宠/常驻/位置记忆等桌面形态做成了窗口原语（一条 meta 声明即得）。全程无 WebView、无 Node、无 Python，构建与验证链只有 C99 + bash。

agent 生成 hn 编码→ Neb 引擎解析·级联·布局→ 探针锚定的像素口径→ 桌面原生窗（桌宠 / 大屏 / 会话窗）

agent 的产物首次获得"机器可验证"的桌面渲染出口：错了探针当场报，而不是用户眼前闪退。

02 — 技 术 架 构

一个引擎核心，三后端 · 双路径 · 全抽象

三层架构全部 C99：Neb 引擎核心（解析/级联/布局/绘制指令，20.6k 行零依赖）→ rt 运行时（QuickJS · 媒体宿主 · GPU 宿主 · 定时器/事件）→ platform 平台胶水（每平台一个 hnp_*.c，运行期 dlopen，编译期零 SDK）。平台只出实现，契约全在 hn_platform.h。

关键机制说明
三后端同源同一份显示列表，hnsoft（纯 C 软件光栅）/ cairo / Metal v1（GPU 原语表）三执行器；简单页 CPU 反而更快，回退逐帧静默
探针锚定渲染24 个探针、1145+ 项断言把渲染口径钉死（颜色/几何/像素采样/跨架构确定性）；每轮回归逐值对账，性能优化不许改变任何像素
GPU 契约hnp_gpu_host 原语表（设备/纹理/四边形/裁剪/读回）：平台出设备原语，引擎出画法；覆盖不了的指令整帧静默回退 hnsoft
零依赖 · 零 SDK引擎与全部工具纯 C99；AppKit/X11/Metal/AVFoundation 全部运行期 dlopen；构建与验证链只有 C99 + bash
媒体 GPU 合成真窗 <video> 走 AVPlayerLayer 原生图层（GPU 合成，解码拷贝链停用）；循环回绕走到尾通知，空洞 0.12s

真窗呈现链：agent 事件/定时器/动画 → 单一显示列表（10 类指令）→ hnsoft 或 Metal → 位图 → 图层直呈；HiDPI 按 backing scale 2x FreeType 光栅。离屏与探针恒 1x 确定性口径。

03 — 应 用 场 景

桌面形态，一条 meta 声明即得

html-native 改变的是 agent 产出到用户桌面的最后一跳——不装应用、不开浏览器，窗口即 UI：

形态场景与收益
桌宠 / 数字人悬浮+无边框+点击穿透+位置记忆+常驻自启；Live2D 官方 motion 数据驱动 rig（视角跟随/呼吸/口型），moc3 专有边界以自有 rig 替代
agent 数据大屏一条指令弹原生窗；markdown/JSON/CSV 直染 + canvas 2D 图表 + sys:// 本地系统桥；流式 update 逐帧热推送
流式会话窗markdown 直染 + IME 中文输入 + hn-stream 自动跟随——agent 会话的原生窗形态，回绕空洞 0.12s
媒体窗<video>/<audio> 走 AVPlayerLayer GPU 合成（CPU 解码拷贝链停用）；GIF/Lottie/dotLottie 直读
常驻小组件几何记忆（拖到哪回哪）+ resident 常驻自启 + 点击穿透"幽灵模式"

实测工作流（media-demo 真窗 60 秒）：RSS 平稳 125.6→128.1MB、循环回绕 12 次空洞 0.12s、CPU ~34% 单核；canvas-demo：JS 定时器驱动实时折线，账本稳态 56 op 有界；events：addEventListener 点击/键盘全链路。全部探针脚本随仓库可复跑。

04 — 创 新 点

四个结构性创新

① 纯 C99 零依赖单文件引擎

解析到像素一条自有管线（Neb = NO-WEB）：无 WebView、无 Node、无 Skia；AppKit/X11/Metal 全部运行期 dlopen，编译期零 SDK——交叉产物即拷即用。

② 探针锚定渲染

24 探针 1145+ 断言把渲染口径钉成机器可验证的契约：颜色/几何/像素采样/跨架构确定性逐位对账；性能优化零像素漂移。

③ GPU 契约 + 静默回退

hnp_gpu_host 原语表（平台出设备原语，引擎出画法）：Metal v1 混合页快 2.4×；覆盖不了的指令整帧静默回退 hnsoft——像素永远正确。

④ 桌宠/常驻原语

悬浮层级、点击穿透、位置记忆、常驻自启做成窗口原语与 meta 声明；视频走 AVPlayerLayer GPU 合成，回绕空洞 0.12s。

05 — 开 源 基 础

生而开源：单仓库 · 全探针 · 全链路可复跑

项目以 MIT 协议在 GitHub 公开迭代，引擎、运行时、平台壳、构建与验证链同仓同源；每轮能力落地都以探针断言收口，回归全绿才合入。

内容说明
Neb 引擎核心（Sources/CHtmlNative）解析 → 级联 → 布局 → 显示列表（10 类指令）→ 三后端光栅；纯 C99 零依赖
rt 运行时（rt/hn_rt.c）QuickJS · JS 事件层 · 定时器/RAF · 媒体/GPU 宿主注入 · sys:// 本地桥
platform 平台层（platform/hnp_*.c）macOS（AppKit/AVFoundation/Metal）/ Linux（X11/Xv）/ headless —— 契约在 hn_platform.h，实现各归各位
验证链（tools/*.sh，24 探针）1145+ 断言：像素采样/账本/事件/媒体生命周期/GPU 等价/跨架构确定性——bash 一条命令全量回归

可复现与可验证：克隆仓库后 bash tools/build-multiplatform.sh 一条命令产出三平台全部产物（含跨架构确定性自检）；bash tools/*_probe.sh 全量回归。平台能力矩阵以 docs/platforms.md 为跟踪账——契约在头文件，平台只有实现差异，降级也写进契约。

06 — 发 展 路 线

两条线：渲染更深，桌面更活

html-native 是"引擎 + 形态"双线项目：渲染线回答"agent 生成的 UI 能不能渲染得更准、更快、更高清"，形态线回答"agent 的 UI 能不能更像桌面原住民"。

线已走过的路（全部公开可查）
渲染线C99 引擎 → 10 类指令三后端 → preserve-3d 矩阵栈与深度排序 → canvas 2D 178 断言 → GPU 原语契约与 Metal v1 → HiDPI 2x 光栅
形态线透明窗 → 悬浮/穿透/跨空间 → 桌宠 → 位置记忆与常驻自启 → 媒体图层 GPU 合成 → Live2D motion 驱动数字人

① 渲染线 → 直呈与全 GPU

Metal 直呈（去 readback）；Linux GL 后端插上同一张原语表；POLYGON 三角化；增量布局。

② 形态线 → 数字人完善

IME 候选窗定位与预编辑高亮；Live2D physics3 仿真；多窗多数字人；Linux 行为级验证。

③ 生态线 → agent 基建

JS 事件层完备化（capture 两相/修饰键管道）；hn dev 热重载 CLI；组件生态与模板市场。

一点思考：agent 时代的渲染引擎，价值不在渲染本身，而在"渲染结果可被机器验证"——探针锚定的像素口径，就是 agent 与像素之间的翻译层。html-native 是这条路上第一个把"验证"做进渲染循环的引擎。
