# 打包与分发

## 项目 = 目录

```
myapp/
  project.json     # {"name":"My App","id":"my-app","entry":"index.html",
                   #  "w":480,"h":720,"version":"1.0.0"}(缺省 index.html 隐式项目)
  index.html
  pages/…  assets/…
```

```bash
dist/hnapp-macos-arm64 myapp/          # 目录即应用
```

- **引擎内页面导航**: `a href` 指向项目内文件 → 同窗换装(hn_rt_navigate/
  back), 页面栈 64 层; 外部 URL 交系统打开。
- **热重载**: 目录递归指纹(FNV-1a 折 路径+mtime_ns+size), 任何被
  include 的片段/共享 css 变化都触发重装载。

## .hnapp 胶囊(ZIP v2)

```
manifest.json + index.html + DOM 遍历收集的本地资产(原子写 tmp+rename)
```

```bash
# daemon/CLI: 打胶囊与拆胶囊
dist/hn persist card ~/myapp.hnapp --instructions "怎么驱动它"
dist/hn restore ~/myapp.hnapp         # 解到 ~/.html-native/apps/<id>/ 按项目模式打开
dist/hnapp-macos-arm64 --capsule ~/myapp.hnapp   # 直启胶囊
```

v1 JSON 胶囊仍可读; 外部 `unzip -t` / python zipfile 双校验通过。

## hn pack — 既有 H5 网页 → 桌面轻应用

```bash
dist/hn pack <file.html | dir | url>   # 兼容性体检 → 注入 hn-* meta → 收集资产
```

- **兼容性体检**: 无头渲染一遍, 对照 hn 子集逐页报告不支持/被忽略特性
  (符合标准的 H5 从口头承诺变成机检);
- **改装**: 原样式零改动, 只注入 hn-* meta(窗口尺寸/无边框/主题);
- **产出**: 项目目录 + .hnapp 胶囊 —— restore 即得桌面轻应用。

## hn build — 人类分发形态

```bash
dist/hn build myapp/ --target macos    # → My App.app(Info.plist+运行时+胶囊)
```

名称/id/版本取 project.json 的 app 字段; `hn_app --capsule` 与 daemon
restore 同口径解包。Windows `.exe` / Linux AppImage 按 roadmap 排期。

## 生命周期哲学

应用是易变对象: 生成(秒开) → 热更新(同 id 推送, 窗口不动) →
持久化(胶囊, 离线可再唤起) → 销毁。与 PWA/小程序同型, 但无浏览器、
无安装、无构建。
